# 微信小程序迁移计划书

## 1. 项目目标

将现有 `autowechatpush` React Web 应用迁移至微信小程序平台，旨在扩展应用触达范围，提升用户在微信生态内的一体化体验。

## 2. 核心策略

- **框架选型**: 采用 **Taro.js** 框架进行开发。鉴于现有前端技术栈为 React，Taro 能够最大化地复用组件、Hooks 及业务逻辑代码，显著降低迁移成本和开发周期。
- **后端服务**: 复用现有的后端 API，服务地址为 `https://www.aiwxcreator.cloud/`。小程序将通过此域名进行数据交互。
- **代码结构**: 建立一个独立的 `mini-program` 目录存放 Taro 项目，与现有 Web 项目和后端项目保持分离，便于维护。

## 3. 迁移阶段与任务分解

### **第一阶段：环境搭建与项目初始化 (预计1天)**

1.  **[已完成]** **确认后端服务**: 后端 API `https://www.aiwxcreator.cloud/` 已部署并支持 HTTPS。
2.  **[待办]** **配置后端 CORS**: 确保后端服务接受来自小程序域名 `servicewechat.com` 的跨域请求。
3.  **[待办]** **安装 Taro CLI**: 在全局环境中安装 Taro 开发工具。
    ```bash
    npm install -g @tarojs/cli
    ```
4.  **[待办]** **创建 Taro 项目**: 在项目根目录下，初始化一个新的 Taro 项目，并选择 React 框架和 TypeScript。
    ```bash
    taro init mini-program
    ```
5.  **[待办]** **配置 Tailwind CSS**: 根据 Taro 官方文档，为新项目集成并配置 `tailwindcss-taro`，以便复用现有样式代码。

### **第二阶段：核心逻辑与基础服务迁移 (预计2天)**

1.  **[待办]** **迁移 `types`**: 复制根目录下的 `types.ts` 及 `backend/src/types` 内的类型定义到 Taro 项目的 `src` 目录中。
2.  **[待办]** **迁移 `services`**: 复制根目录下的 `services` 文件夹到 Taro 项目的 `src` 目录中。`apiClient.ts` 中的 `axios` 实例在 Taro 中可基本兼容。
3.  **[待办]** **改造认证逻辑 (`AuthContext`)**:
    - 复制 `components/AuthContext.tsx` 到 Taro 项目中。
    - 将所有 `localStorage` 的调用替换为 Taro 的同步存储 API：`Taro.setStorageSync()` / `Taro.getStorageSync()`。

### **第三阶段：页面与组件迁移 (预计5-7天，迭代进行)**

1.  **[待办]** **配置页面路由**:
    - 分析原 `App.tsx` 中的路由定义。
    - 在 Taro 项目的 `src/app.config.ts` 的 `pages` 数组中，为每个页面创建对应的路径。
2.  **[待办]** **逐个迁移页面与组件**:
    - 从最简单的页面开始（如 `WelcomePage`、`AuthPage`）。
    - 复制组件代码，Taro 会自动转换 JSX 标签 (`div` -> `View`)。
    - 将 `react-router-dom` 的导航（如 `<Link>`, `useNavigate`）替换为 Taro 的路由 API（如 `<Navigator>`, `Taro.navigateTo`）。
    - 验证每个页面的布局和功能。

### **第四阶段：关键功能替换 (预计3-4天)**

1.  **[待办]** **替换富文本编辑器**:
    - **分析**: 现有 `Editor.tsx` 组件无法直接迁移。
    - **方案**: 调研并选择一个成熟的小程序富文本编辑器组件（如 `mp-html` 或小程序原生 `<editor>` 组件）。
    - **实现**: 在 Taro 项目中重新实现文章编辑功能，确保其核心功能（文本格式化、图片插入等）与原编辑器体验接近。这是本次迁移的技术重点和难点。

### **第五阶段：联调测试与发布 (预计3天)**

1.  **[待办]** **整体功能联调**: 在微信开发者工具中，全面测试所有页面和功能，包括登录、内容生成、编辑、预览等。
2.  **[待办]** **修复 Bug**: 解决测试过程中发现的各种兼容性问题和 Bug。
3.  **[待办]** **打包与部署**:
    - 执行 `taro build --type weapp` 命令打包小程序。
    - 使用微信开发者工具上传代码包，提交审核并发布。

## 4. 风险评估

- **富文本编辑器**: 迁移工作量的核心不确定性在于富文本编辑器的替换。新组件可能无法 100% 还原当前编辑器的所有功能和体验。
- **第三方库兼容性**: 部分 Web 端专用的 React 库可能在小程序中没有对应的替代品，需要寻找解决方案或进行功能降级。
